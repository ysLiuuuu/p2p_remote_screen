# BlueZ 蓝牙配网协议

设备通过 BlueZ D-Bus 导出一个自定义 GATT 服务，并注册可连接的 LE 广播。

- Service UUID：`7b7f0000-6e7d-4c8d-9f4b-8f57e34a9100`
- 数据编码：UTF-8 JSON
- 单次写入上限：4096 字节
- 配置文件以 `0600` 权限原子替换，避免掉电留下半份 JSON

## GATT 特征

| 名称 | UUID 尾号 | 属性 | JSON |
|---|---:|---|---|
| DeviceInfo | `0001` | Read | `name`、`role`、`model`、`version` |
| NetworkConfig | `0002` | Read/Write | `role`、`device_name`、`go`、`gc` |
| PairCommand | `0003` | Write | `{"command":"start|cancel|clear"}` |
| VideoConfig | `0004` | Read/Write | 视频参数对象，保存到配置的 `video` 字段 |
| DeviceControl | `0005` | Write | `{"command":"start|stop|restart|factory_reset"}` |
| Status | `0006` | Read/Notify | `network`、`media`、`error` 等运行状态 |

完整 UUID 的生成方式是将 Service UUID 中的 `0000` 换为表中的尾号。
NetworkConfig 和 VideoConfig 写成功后立即持久化；PairCommand 和
DeviceControl 通过 `BleManager::WriteCallback` 交给设备状态机执行。

NetworkConfig 示例：

```json
{
  "role": "gc",
  "device_name": "WD-LCAT-RX",
  "gc": {
    "go_devname": "WD-OPI-TX",
    "fallback_ip": "192.168.49.100/24"
  }
}
```

## 运行

BLE 可随 `p2p_manager` 一起启动，也可独立运行，便于 systemd 分开托管：

```bash
sudo ./ble_provisioner /etc/wireless-display/config.json
```

配置项：

```json
{
  "ble_enabled": true,
  "ble_adapter": "hci0",
  "ble_name": "WD-OPI-TX"
}
```

运行依赖 `bluetooth.service`、system D-Bus 和 `libdbus-1.so.3`。进程通常需
以 root 运行，或者为其配置允许调用 BlueZ GATT/Advertising Manager 的
D-Bus policy。

当前协议完成了数据长度、JSON 结构和命令白名单校验。产品化前仍应启用
BLE 配对/加密，并在写请求回调中增加设备验证码、配置窗口超时和授权校验。
