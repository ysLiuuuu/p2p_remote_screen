# HDMI 无线媒体链路

## 数据路径

```text
OPI / RK3588（发射端）
/dev/video0 BGR24 → RGA DMA-BUF 转 NV12 → Rockchip MPP H.264 编码
→ H.264 Annex-B 帧分片 → UDP → Wi-Fi Direct

LCAT / RK3576（接收端）
UDP 帧重组 → Rockchip MPP H.264 解码（强制线性 NV12）
→ MPP DMA-BUF 导入 DRM framebuffer → Plane 直接输出 HDMI-A-1
```

编码器与解码器均采用 Rockchip MPP 官方 MPI 使用流程：`mpp_create`、
`mpp_init`、配置对象、帧/包队列和解码 `info_change` 外部缓冲组。编码端在
每个 IDR 前附加 SPS/PPS；UDP 丢失造成不完整帧时接收端直接丢弃，并在下一
个 IDR 自动恢复。

当前传输层是项目自有的轻量 UDP 帧分片协议（魔数 `WDHM`，单个 UDP 负载
1320 字节），不是标准 RTP。它用于先完成低延迟端到端闭环；如需与第三方
播放器互通，再将该层替换为 RFC 6184 H.264/RTP 即可，MPP 和 DRM 部分无需改动。

## 构建、部署与运行

```bash
./scripts/build_media.sh
./scripts/deploy_media.sh

# 自动建立 Wi-Fi Direct（未建链时）并启动两端
./scripts/run_media.sh start-p2p

# 查看实时帧率、码率和丢帧数
./scripts/run_media.sh status

# 只停止媒体进程，保留 P2P
./scripts/run_media.sh stop

# 停止媒体并拆除 P2P、恢复 NetworkManager
./scripts/run_media.sh teardown
```

排除无线问题时可改走固定有线网段：

```bash
./scripts/run_media.sh start-wired
```

默认参数为 1920×1080@60 fps、H.264 CBR 10 Mbit/s、UDP 5004。可以通过
环境变量覆盖码率，例如：

```bash
BITRATE=8000000 ./scripts/run_media.sh start-p2p
```

## 已验证结果

- OPI HDMI RX：1920×1080 BGR24，RGA 转换及 MPP H.264 硬编码约 60 fps。
- 有线固定网段：约 12 Mbit/s，LCAT 接收、MPP 解码和 DRM HDMI 显示跑通。
- Wi-Fi Direct：GO `192.168.49.1`、GC DHCP `192.168.49.2`，10 Mbit/s 下
  稳定段实测约 57–59 encoded/displayed fps；扩大 RX UDP 缓冲后连续测试
  `transport_drop=0`。即便后续发生无线丢包，不完整帧也会被丢弃并在下一
  个 IDR 自动恢复。
- LCAT 显示：HDMI-A-1 / CRTC 89 / NV12 Plane 56，输出模式 2560×1440@60。
